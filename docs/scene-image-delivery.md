# 2.5D画像の配信と読み込み

現在の人物はGPT Imageで再生成したv2です。人物は `*-v2.png` を原本、`*-v2.webp` を配信先とし、v1も保存しています。[再生成内容](portrait-refresh.md)。

背景3枚・人物12枚のPNG原本を保存したまま、同じフォルダー・同じ名前の `.webp` を配信用に追加しました。場所選択、行動選択、会話画面は共通の画像設定からWebPを参照します。

## 変換内容

- 可逆圧縮のみ。リサイズ、トリミング、再生成、色調や顔の編集はありません。
- 全15枚について寸法、透明度、透明度が0以外の全RGB画素が変換前後で一致することをデコードして比較しました。完全透明画素内の見えないRGB値はWebPで破棄される場合があります。
- 元PNG合計26,372,737バイト → 配信用WebP合計16,254,320バイト（約38%削減）。原本も保存するため、リポジトリと配備ファイルの総量自体は増えます。ブラウザから原本のPNGは参照しません。
- 各ファイルの寸法・容量・SHA-256は `scene-image-sizes.json` に保存しています。自動テストは設定にある15ファイルと原本がこの記録に一致するかを検査します。

既存のsharpが使える制作環境で再変換する場合：

```sh
node scripts/optimize-scene-images.mjs /absolute/path/to/node_modules/sharp
```

引数省略時は通常のモジュール解決を使います。sharpは素材制作時だけ使うもので、アプリの依存関係には追加していません。会話アプリの起動やビルドで変換処理は実行しません。PNGを差し替えた場合は、WebPと検証記録も作り直してください。

## 読み込みの動作

会話画面は背景と現在の表情を優先して読み込み、残りの表情も低優先度で準備します。現在必要な画像を読み込んでいる間は短い案内を表示します。表情はデコードできるまで直前の画像を維持し、準備ができたら既存のフェードで切り替えます。最初の画像が未準備の場合もセリフや入力操作は利用できます。

背景または必要な表情を読めない場合は、文章で会話を続けられる案内と「画像を再読み込み」ボタンを表示します。画像だけを再読み込みし、セッション・会話・入力・読み上げコンポーネントをリセットしません。未使用の表情の読み込み失敗だけで警告は表示しません。人物または場所が変わると画像状態を初期化します。

人物の枠・背景の構図・既存の動き軽減設定を維持しています。読み込み案内は画像の上に配置し、画像の位置や会話入力欄を押し下げません。動き軽減時は表情フェードと背景ズームを停止します。

## 確認の範囲

変換前後の全画素比較（完全透明画素のRGBを除く）、画像の整合性、表情の遅延・失敗・回復・遅着時の選択を確認しました。150テストと型チェック・ビルドが成功しました。ローカルHTTPから15枚すべてを取得し、image/webpの応答と内容のSHA-256、ビルド配備先へのコピー一致も確認しています。元画像に埋め込みICCプロファイルはありませんでした。

ブラウザ接続とWindowsでのURL確認が利用できなかったため、PC・スマホの目視確認、回線を絞った実ブラウザの読み込み、ソフトキーボード表示時の確認は別途必要です。自動テストは画像の選択状態を検査するもので、実ブラウザのフェード描画やボタン操作の確認を代替しません。

追加検証：独立したヘッドレスEdgeではPC・スマホ相当の画像表示と再読み込み操作を検証できました。スクリーンショットも確認しています。詳細と実機で残る確認は `browser-verification.md` を参照してください。
